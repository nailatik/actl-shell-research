# План реализации

## 0. Зафиксировать требования

Согласовать форму запуска, синтаксис встроенных команд, границу временного backend. На выходе - состав MVP и список отложенных функций.

## 1. Собрать каркас REPL

- запуск и завершение shell;
- prompt;
- постоянная история и `Ctrl+R`;
- стандартное редактирование строки;
- корректные `Ctrl+C`, `Ctrl+D`, `exit`, `quit`;
- ошибка отдельной команды возвращает следующий prompt.

## 2. Реализовать каталог команд и контексты

- восемь корневых модулей;
- `packages/apt`, `packages/rpm`, `packages/repo`;
- `modules`, `ls`, `use`, `back`, `root`, `pwd`, `help`;
- относительные и абсолютные команды;
- статическая справка и completion из одного Command Catalog.

## 3. Подключить существующие команды

Подключить все команды текущего `actl`, сохранив аргументы, подтверждения и обработку ошибок.

Для каждого модуля нужен smoke-тест. Последовательные вызовы проверяются отдельно: параметры не должны протекать между командами.

## 4. Добавить возможности постоянной сессии

- объектный контекст и динамическое completion для `services`;
- timeout и кэш completion;
- `history save` и простые сценарии через `source`;
- номера строк и `stop-on-error` для сценариев;
- корректный progress длительных операций.

## 5. Стабилизировать MVP

- сохранено Polkit-поведение текущего CLI;
- проверены подтверждения опасных операций;
- история не сохраняет чувствительные данные;
- help и completion покрывают все команды;
- описаны ограничения;
- подготовлены законченные пользовательские сессии и документация.

## Функциональное покрытие

1. `components`.
2. `diag`.
3. `editions`.
4. `manager`.
5. `packages` с подмодулями `apt`, `rpm`, `repo`.
6. `services`.
7. `sources`.
8. `systeminfo`.

Для каждого модуля работают команды, `help`, статическое completion и абсолютный вызов.

Глубокий object context в MVP проверяется только на `services`.

## [После MVP](./future.md)

- типизированные результаты и `let`;
- `watch` и подписки на события;
- фоновые jobs;
- `plan` там, где его поддерживает backend;
- TUI;
- общее плагинное ядро и автоматический рендеринг;
- `remote`.

## Критерий завершения MVP

Пользователь может войти в любой модуль, найти команду через help или Tab, выполнить её относительно контекста либо абсолютным путём, повторить из истории, продолжить после ошибки, запустить простой сценарий и безопасно выйти.
