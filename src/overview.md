# Краткий обзор

## Цель

`actl-shell` - интерактивный режим для многошаговой работы с Alterator. Он сокращает повторный ввод, помогает находить команды и хранит контекст между ними.

Обычный `actl` остаётся предпочтительным для одной заранее известной команды, cron, CI и внешних shell-скриптов.

## Что даёт shell

- постоянная сессия без повторного запуска приложения;
- навигация по модулям и подмодулям;
- контекстный prompt;
- справка и completion текущего контекста;
- история, поиск и редактирование команд;
- абсолютный вызов команды без выхода из текущего контекста;
- безопасные настройки сессии;
- простые воспроизводимые сценарии через `script`;
- продолжение сессии после ошибки.

## Пример взаимодействия

```text
$ actl-shell
actl> use packages
actl:packages> use apt
actl:packages/apt> search samba
actl:packages/apt> /systeminfo arch
x86_64
actl:packages/apt> back
actl:packages> root
actl> exit
```

Относительная команда выполняется в текущем контексте:

```text
actl:packages/apt> list
```

Абсолютная команда - от корня:

```text
actl:packages/apt> /services list
```

Командный контекст и выбранный объект хранятся отдельно. Здесь `services` - модуль, а `samba` - объект:

```text
actl> use services
actl:services> use samba
actl:services/samba> status
```

Объектный контекст сначала проверяется на `services`. Остальным модулям в MVP достаточно контекста модуля и полного набора команд.

## Первая версия

Первая версия включает все восемь модулей текущего `actl`: `components`, `diag`, `editions`, `manager`, `packages`, `services`, `sources`, `systeminfo`. Кроме их команд, нужны:

- `modules`, `ls`, `use`, `back`, `root`, `pwd`, `help`;
- контекстный prompt;
- статическое completion всех модулей и команд;
- одно динамическое completion для `services`;
- постоянная история, `Ctrl+R` и сохранение выбранного диапазона в сценарий;
- выполнение файлов через `script`;
- существующие подтверждения, Polkit и обработка сигналов.
