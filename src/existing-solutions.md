# Анализ аналогов

## apt-shell

`apt-shell` входит в ALT-версию APT-RPM. Он работает с одним загруженным кэшем пакетов: `install`, `remove`, `keep`, `upgrade` и `dist-upgrade` меняют выбранное состояние, `status` показывает его, а `commit` применяет изменения.

```text
apt> install package
apt> status
apt> commit
```

Команды `show`, `list` и `search` позволяют исследовать пакеты, не выходя из сессии, а `script` выполняет команды из файла.

Полезные идеи:

- повторное использование загруженного состояния между командами;
- просмотр подготовленных изменений перед применением;
- явная граница `commit`;
- один набор команд для интерактивной работы и файлов сценариев.

Но его модель переносится не целиком:

- `apt-shell` работает в одной предметной области и использует решатель APT;
- операции разных модулей Alterator не образуют общую транзакцию;
- общий `begin/commit/rollback` для `actl-shell` обещать нельзя;
- отложенное выполнение имеет смысл только для операций, чей backend поддерживает preview/plan.

Для `actl-shell` полезны постоянная сессия, повторное использование загруженных данных и выполнение сценариев тем же обработчиком команд. 

Источники:

- встроенная справка `apt-shell` из пакета `apt-0.5.15lorg2-alt103`;
- [пакет APT в ALT Linux](https://packages.altlinux.org/ru/sisyphus/srpms/apt/);
- [исходный код APT-RPM](https://git.altlinux.org/gears/a/apt.git).

## bluetoothctl

`bluetoothctl` - интерактивный клиент BlueZ. Общий shell на GNU Readline регистрирует меню и команды декларативными таблицами.

Пользователь входит в подменю командой:

```text
[bluetoothctl]> menu gatt
```

и возвращается командой:

```text
[bluetoothctl]> back
```

Полезные решения:

- набор допустимых команд зависит от активного меню;
- `help` показывает команды активного меню;
- у команды может быть собственный динамический completion generator;
- общие `help`, `back`, `exit`, `script` доступны централизованно;
- `Ctrl+C` отменяет текущий ввод, а не обязательно завершает программу;
- одна shell-инфраструктура повторно используется несколькими утилитами BlueZ.

Что не подходит:

- `back` возвращает в главное menu, а не к произвольному родителю;
- активное меню не отображается в prompt как путь;
- menu context и выбранное устройство/атрибут являются разными видами состояния;
- асинхронный вывод усложняет автоматизацию и перерисовку prompt.

Для `actl-shell` нужны menu commands и автодополнения каждой команды, но с деревом контекстов, пошаговым `back`, абсолютными путями и контекстом в prompt.

Подробная модель перенесена в [«Контекст и навигация»](./context.md).

Источники:

- [bluetoothctl documentation](https://github.com/bluez/bluez/blob/master/doc/bluetoothctl.rst)
- [BlueZ shared shell](https://github.com/bluez/bluez/blob/master/src/shared/shell.c)
- [bluetoothctl command registration](https://github.com/bluez/bluez/blob/master/client/main.c)
